# 格雷（GregTech CEu Modern）↔ 启动修复模组 版本对照表

> 模组全名：GTM JEI Startup Crash Fix（mod id `gtm_jei_startup_fix`），修的是
> **Minecraft 1.21.1 + NeoForge + 格雷 8.0.0-SNAPSHOT** 启动崩溃等五个问题。
> 本表最后更新：修复模组 **r57**（已核对到格雷快照 `+c72e0cf`，Maven build 126）。

## 一、先说结论（玩家只看这段就够）

1. **不管你的格雷是下表里的哪一个快照，都直接装最新版修复模组（目前 r57）。**
   修复挂钩用到的所有类与方法签名，从 `17e1700` 一路到 `c72e0cf` 是逐级逐条核对过的
   （r57 这轮格雷内部重构了一个类，但**我们挂钩用到的那部分一字未变**，见〈二〉末段）；
   最早的 `34f02a6` 当时也实测可用，且新老快照的形态差异（r14 起）都能兼容——
   所以最新一颗 jar 通吃整条链。
2. **r40 ~ r43 这四颗绝对不要用**——它们的包有个元数据笔误，装上去客户端**启动就崩**
   （不是格雷的问题，是补丁包自己的问题）。r45 已修好；只要用 r45 及之后的就没这个坑。
3. **修复模组只装在客户端**（每位玩家自己的电脑上）。服务端不用装；r45 起就算误装到服务端
   也只是闲置一句话，不会拖垮开服。

## 二、按「格雷快照」查（你装的是哪个格雷？）

格雷的版本串长这样：`8.0.0-SNAPSHOT+c72e0cf`——加号后面那 7 位就是快照号，
怎么在游戏里查到自己的版本见〈四〉。

| 格雷快照（`+` 后 7 位） | Maven 构建号 | 格雷发布日期（UTC） | 当年是哪个修复版核对的 | 现在用 r57 |
| --- | --- | --- | --- | --- |
| `34f02a6` | —（早于有记录的构建号） | 2026-09（较早） | r5 ~ r13（本模组就是为修它而生） | ✅ |
| `17e1700` | — | 2026-09 | r14 起适配，r14 ~ r38 都按它核对 | ✅ |
| `01bda09` | 96 | 2026-09-26 | r39 | ✅ |
| `3a1493f` | 100 | 2026-09-29 | r43 核对（包缺陷在 r45 修好，结论继续有效） | ✅ |
| `d2ef26f` | 101 | 2026-10-01 | r46 | ✅ |
| `e297c53` | 103 | 2026-10-03 | r47 | ✅ |
| `4a05735` | 104 | 2026-10-07 | r49 | ✅ |
| `4157773` | 106 | 2026-10-07 | r50 | ✅ |
| `d208a65` | 109 | 2026-10-09 | r51 | ✅ |
| `d73adfb` | 115 | 2026-10-10 | r52 核对、**r52 没出包**，凭据随 r53 交付 | ✅ |
| `36a6b38` | 124 | 2026-10-17 | r55 | ✅ |
| `c72e0cf` | 126 | 2026-10-24 | **r57（当前最新成品）** | ✅（就是它） |

「✅ 现在用 r57」的依据：从 r39 起，格雷每出一个新快照，我们都从格雷官方 Maven 下载
**与玩家实装同一构建号的 jar**，把修复模组挂钩用到的每一个类、每一个方法签名逐条 `javap`
反汇编比对。`34f02a6` → `36a6b38` 相邻两级之间全部**零漂移**（签名一字不差）；
`36a6b38` → `c72e0cf` 这轮格雷头一回真动了我们钉过的类——`GTRegistries`（配方分类注册表）
被上游重构，删掉了它自己内部那套延迟注册管线，也新增了注册表字段。但逐条核对下来
**对我们的补丁零影响**：我们只反射读它的 `RECIPE_CATEGORIES` 一个公开字段，这一项两版
逐字节一致，注册照样在 JEI 加载之前就填好。其余 18 个钉点类零漂移，崩溃链本身则原样存在——
也就是说格雷一直没修这个问题，我们的补丁对表里任何一档都继续有效、一个修复都不能少。

**你的快照不在表里？**（比如 97~99、102、105、107~108、110~114、116~123、125 这些没被实装核对过的中间构建）
不能打包票，但按相邻档全部零漂移的规律，几乎可以肯定照样能用。装好后启动一次，
进游戏输入 `/gtmfix status`：本模组自带自检（r36 起），真没生效它会明说「⚠ 本次可能未生效」，
并且把日志路径指给你——那种情况请把日志发回来，我们加一行核对。

## 四、怎么查自己的版本

- **格雷版本**：`mods` 文件夹里 `gtceu-…jar` 的文件名，或游戏主菜单 →「模组」列表里的
  `GregTech 8.0.0-SNAPSHOT+xxxxxxxx`，或启动日志里 Mod List 那一行——`+` 后 7 位就是快照号。
- **修复模组版本**：jar 文件名末尾 r 号；进游戏 `/gtmfix status` 也念一遍；
  日志 `gtm_jei_logs/startup-*.log` 头部「本模组版本」一行同样有。
- **JEI 版本**：模组列表里 `Just Enough Items 19.xx`。

## 五、对照表背后的环境要求

| 项目 | 要求 |
| --- | --- |
| Minecraft | 1.21.1（仅此版本） |
| NeoForge（加载器：给游戏装模组的底座） | 21.1.x，最低 21.1.235（实测 21.1.244 / 251） |
| GregTech CEu Modern（`gtceu`） | 8.0.0-SNAPSHOT，快照见上表 |
| JEI | 19.x（实测 19.27 / 19.56 / 19.57；格雷自身要求 ≥19.25.1.328） |
| ModularUI（格雷的界面库） | **不用单独装**——格雷 jar 内嵌了 3.3.1-SNAPSHOT；核对到 r57：内嵌件在 build 124 换过一次件（r55 已逐条目比对、对我们的修复零影响），build 126 与 build 124 逐字节相同 |

## 六、五项修复各治什么（对号入座）

| # | 症状 | 从哪个 r 号修好 |
| --- | --- | --- |
| 1 | 游戏启动直接崩（格雷图标抢跑调用没准备好的 JEI） | r5 |
| 2 | JEI 里一个格雷配方分类都看不到 | r13 |
| 3 | 点开格雷配方页（如搅拌机）必崩 | r17 |
| 4 | 多方块机器的 3D 结构预览图偏到左上角 | r24 |
| 5 | 控制器「可使用的类型」弹出菜单开出屏幕外 | r28（r31 摆法才到位） |

## 七、不在本表范围

- **Minecraft 1.20.1 / Forge 版格雷**：同样的毛病也存在，但移植目前只有方案文档
  （`docs/port-plan-forge-1.20.1.md`），**还没有成品包**，别指望这颗 jar 能装进去。
- 格雷 7.x 及更早、1.12.2 GTCEU 等其他线/其他大版本。
- 格雷快照链之外的正式 release（如将来 8.0.0 正式版）——出了会另核对、另更新本表。
